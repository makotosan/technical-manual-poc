## 結果と正本

- 基本図24点＋表紙PNG/銘板2点の追加3点＝掲載27図。原画の表紙SVGは代替素材で二重計数しません。
- 基本受入表18点（仕様3、運転設定4、点検4、故障3、ラベル2、文書管理2）＋追加編集表36点＝54表。残留リスク12件等を消して件数合わせはしません。
- 警告18種: DANGER 2、WARNING 8、CAUTION 5、NOTICE 3。複数章で同じ文を使うため掲載回数は18より多くなります。
- 正本: sample-data/visual-inventory.json、sample-data/safety-messages.json。各図・表は出典原稿と安定IDで追跡します。台帳IDの空き番号は再利用しません。

## 共通変換

原稿の独立行に [[safety:W-02]] のような参照を置き、EleventyのMarkdownライブラリへ登録したlib/safety-messages.mjsがHTMLを生成します。
PDF用の警告文や別Markdown変換は作りません。NOTICEは人的危害の警告シンボルを付けず、情報表示とします。
危険図は独自SVG概念図です。危険図と、信号語の横にある一般の安全警告三角形は別要素です。
W-01はW-05へ、旧C-01の転倒情報はWARNING W-06（H-05/H-08）へ対応づけ、旧符号を表示・台帳で保持します。
H-01〜H-10の参照を検証します。規格登録標識やANSI色の厳密適合は主張せず#22でレビューします。

CSSはmanual-v02/styles/safety.css。左の狭い図記号領域、右の縦罫線、インライン信号語、太字の主題、危害・回避文を共通の構造で表示します。
画面と印刷で同じ内容を使い、狭幅・グレースケールでも色だけに頼らず区別できます。
通常の警告は改ページを避け、極端な長文はsafety-longで分割を許容します。長文クラスの選択は自動テスト、実PDFは現在の18種と長表で検証します。

## 実行

npm run visual:build:web
npm run visual:test
npm run visual:browser

visual:browserはWindowsの既設Chromeを既定とし、別環境はVISUAL_BROWSER_PATHで実行パスを指定します。
検証出力はdist-visual-web/、dist-visual-pdf/、dist-visual-review/です。公開のdist-web/はv0.1のままです。
Eleventyが生成したindex.htmlをローカル配信し、同じHTML URLをVivliostyleへ入力します。生成前後のHTMLハッシュ一致と画像・CSS・フォント読込みを検査します。

検証PDFは全18警告、34行の詳細点検表、SVGとPNGを含む7ページです。HTMLとPDFで全危害文・回避文が一致、長表が複数ページへ分割され見出しが反復、A4であることを検査します。
画面は1100px/390px、グレースケール、Tabでのリンクフォーカス、全27図版の読込みを確認します。画像はdocs/visual-review/に保存。

## #13への引継ぎ

長文版の章別HTML選択とURL変換は#13で行います。safetyMarkdown(md, options)のassetPrefix/referencePrefixで章と付録の相対パスを設定し、実際の章出力名にリンクを合わせる必要があります。
このIssueの独立検証画面は短い#16の本文へ長文原稿を混ぜません。v0.2本文に未変換のマーカーを残したまま公開しないこと。

検証用の付録C参照先はリンク確認のための入口です。全統合一覧の最終HTML化は#13で実装します。
